## 1. Goal
No surprise renewals:
- a Renewal Radar 12 months out with deterministic confidence;
- a Renewal Brief;
- a forecast that opens into proof;
- an ARR waterfall and an invoice-level billing forecast;
- money at risk;
- an expansion pipeline with labelled estimates.

## 2. In scope
- **Models** ([W], RLS, composite FKs):
  - `Renewal` (accountId, contractId, renewalDate, noticeDeadline?, arrAtRiskMinor, confidence 0–100, confidenceBand, `confidenceReasons` JSON with sources, stage, planSteps, briefDocumentId?, outcomeArrMinor?), unique `(workspaceId, contractId, renewalDate)`.
  - `ExpansionOpportunity` (accountId, source signal ids, estimateMinor, estimateMethod, isEstimate=true, ownerId, nextStep, nextStepDate, status, crmExternalId?).
  - `Document` if not yet present (kinds incl. `RENEWAL_BRIEF`; `metrics` locked JSON + `narrative` blocks with `{{metric.key}}` placeholders).
  - `RevenueEvent` (exists from M2): extend its rules.
- **`src/modules/renewals/`**:
  - `confidence.ts` (deterministic, test-first). Factors:
    - health band + 30-day trend;
    - open CRITICAL/WARN risk signals;
    - champion status (active / silent / left);
    - late promises (0 until M9 provides Promise; the factor returns `null`, not 0 — Rule 4);
    - failed/late invoices;
    - days to notice deadline vs plan existence;
    - usage vs own baseline.
    Each factor contributes signed points with a reason and `sources[]`. Confidence is clamped 0–100, band `HIGH ≥ 70 / MEDIUM 40–69 / LOW < 40` (config). Factor weights live in `WorkspaceSettings`, with defaults documented in DECISIONS.
  - `radar.service.ts`: the `renewals.sync` job creates/updates `Renewal` rows for every contract with a renewalDate in the next 12 months and opens `RENEWAL_WINDOW_90/60/30` signals (rules from M3, if already present, are reused, not duplicated). A contract with no renewal date → missing-data prompt (M2 helper), not a guessed date.
  - `forecast.ts`: team forecast = Σ ARR by confidence band and stage for a period, each figure listing the contributing Renewal ids.
  - The Renewal Brief: a `Document(kind=RENEWAL_BRIEF)`.
    - `metrics` (locked): health + why, goals achieved, open risks, promise status, expansion chance.
    - `narrative`: the Renewal Manager output, which uses `{{metric.*}}` placeholders only.
- **`src/modules/expansion/`**:
  - Rules: `USAGE_PAID_LIMIT` (seats/credits ≥ 95% of purchased, or over), `NEW_TEAM_USING` (new cluster of users from a new department/email subdomain/team property), `FAST_GROWTH` (active users +X% vs own baseline over 60d), `GOAL_STATED_EXPANSION` (from Goal rows).
  - `estimate.ts` (deterministic, test-first):
    - methods `SEATS_OVER_LIMIT` (extra seats × current per-seat price from the subscription) and `TIER_UPGRADE_DELTA` (from the pricing of *their* plans in subscription data, never from our `src/config/pricing.ts`);
    - when the price per seat is unknown, the estimate is `null` with the label "No price on file";
    - always `isEstimate=true`, labelled "Estimate" in the UI with the method shown.
  - `ExpansionOpportunity` service; CRM export via `integrations.writeBack` (refused unless write-back is enabled → shows "Turn on write-back for HubSpot to sync").
- **`src/modules/revenue/`**:
  - `waterfall.ts` (test-first): opening ARR + new + expansion − contraction − churn (+ reactivation) = closing ARR for a period, from RevenueEvent; every bar opens the events.
  - `billingForecast.ts`: invoice-level forecast from each subscription's interval and currentPeriodEnd (Stripe/Chargebee/CSV).
  - `moneyAtRisk.ts`: ARR of accounts At Risk or with LOW-confidence renewals in the next 30/90 days.
  - `coverage.ts`: accounts with no touch in N days (config, default 30).
  - `teamLoad.ts`: accounts, ARR and open tasks per CSM.
- **Agents**:
  - `renewal-manager`: standard tier. Trigger: `RENEWAL_WINDOW_90` signal. Output: plan steps, talk track, outreach draft (→ Approval), next step with date (→ Task).
    `forbiddenNumericFields: ["confidence","arrAtRisk","expansionEstimate"]`. Prompt: `prompts/renewal-manager.md`.
  - `expansion-finder`: standard tier. Trigger: expansion signals. Output: opportunity narrative + conversation draft ("never a hard pitch with no proof"; must cite the usage/limit records).
    Forbidden: `estimate`. Prompt: `prompts/expansion-finder.md`.
- **OutcomeRecord checkpoints**: `outcomes.checkpoint` now evaluates RENEWED / EXPANDED / CONTRACTED / CHURNED from RevenueEvent/Renewal stage, and computes `valueSavedMinor` / `valueExpandedMinor` per ARCH §6.5 (labelled attributed, Q-15).
- **Screens** (all money passes `redactFinancials` → "Restricted" without `canViewRevenue`):
  - `/renewals` (Renewal Radar): next 12 months; filters 30/60/90/180/365 days, owner, band; confidence with reasons on click; stage; plan; paginated.
  - Renewal Brief page.
  - `/expansion`: pipeline with estimates labelled, owner, next step, status; export to CRM.
  - `/revenue` (Revenue & risk home): money at risk 30/90, forecast, ARR waterfall, billing forecast, coverage, team load.
  - Account 360 › Renewal panel.

## 5. Tests to write FIRST
- `src/modules/renewals/__tests__/confidence.test.ts`:
  - each factor's sign and bounds;
  - clamped at 0/100;
  - band edges 39/40/69/70;
  - missing data → factor `null` and excluded, never lowering confidence (Rule 4);
  - every factor has ≥ 1 source;
  - a hand-built Northgate-like fixture → an exact figure with an exact reason list (exact figures live only in the unit fixture; on the seed the test asserts the tie group and Northgate's reasons, never a tuned number: D2).
- `src/modules/renewals/__tests__/forecast.test.ts`: sums equal the contributing renewals; each figure lists its renewal ids.
- `src/modules/revenue/__tests__/waterfall.test.ts`:
  - opening + movements = closing for the seed fixture;
  - churn and reactivation in the same period;
  - currency handling per Q-12 default (single base currency; non-base rows flagged, not silently converted).
- `src/modules/revenue/__tests__/billingForecast.test.ts`: monthly/annual intervals; a cancelled subscription excluded after period end.
- `src/modules/expansion/__tests__/estimate.test.ts`: 12 seats × per-seat price; unknown price → `null` + "No price on file"; `isEstimate` always true.
- `src/modules/signals/__tests__/fixtures/{USAGE_PAID_LIMIT,NEW_TEAM_USING,FAST_GROWTH,GOAL_STATED_EXPANSION}/*.json`: fire + not-fire cases.
- `src/modules/agents/__tests__/forbidden-numeric.test.ts`: when the renewal-manager / expansion-finder output includes confidence/ARR/estimate values, they are overwritten by deterministic values before persist, and rendered values equal the deterministic ones.
- `src/modules/success-plans/__tests__/narrative-placeholders.test.ts` (or under `renewals` if Document lives there for now): a narrative containing a free-text number that matches a metric is rejected; placeholders render the locked metric.
- `src/modules/revenue/__tests__/redaction.int.test.ts`: every new action/query as a CSM without `canViewRevenue` returns "Restricted" for all money fields.
- `src/modules/outcomes/__tests__/checkpoint-revenue.test.ts`: RENEWED/EXPANDED/CONTRACTED/CHURNED from RevenueEvent; valueSaved only when ACTED + RENEWED/RECOVERED.
