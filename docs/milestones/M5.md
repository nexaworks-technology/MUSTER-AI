## 1. Goal
The adapter framework and the first live connectors (HubSpot, Salesforce, Stripe, Chargebee, Slack), with a gated write-back and a guided setup flow, so that a buyer can go live from HubSpot/Stripe on day 1.

## 2. In scope
- **Models** ([W], with RLS policy, composite unique `(workspaceId, id)`, composite FKs):
  - `Integration`: provider, status, `credentialsEnc`, scopes, `writeBackEnabled` (default **false**), `writeBackFields[]`, lastSyncAt, `lastErrorPlain`, config.
  - `SyncJob`.
  - `WebhookEvent`, unique `(workspaceId, integrationId, externalEventId)`.
  - `ExternalRef` already exists from M2; extend it with `integrationId` usage.
- **`src/modules/integrations/` framework**:
  - `adapter.ts`: the `IntegrationAdapter<Cfg>` interface exactly as in ARCHITECTURE §8.1 (auth oauth2 | apiKey, `testConnection`, `sync` async iterable of `NormalizedBatch`, `webhook.verify/toEvents`, `writeBack`, `describeError`).
  - `normalized.ts`: Zod schemas for `NormalizedAccount`, `NormalizedContact`, `NormalizedInvoice`, `NormalizedSubscription`, `NormalizedContract`, `NormalizedOwner`.
  - `ingest.service.ts`: the single upsert path from normalized records into `accounts`/`contacts`/`billing` through `ExternalRef`. It is idempotent and emits outbox events.
  - `oauth.ts`: OAuth flow with a signed `state` (CSRF), token exchange and refresh. Credentials are encrypted with `src/lib/crypto` (AES-256-GCM, `FIELD_ENCRYPTION_KEY`, key-id prefix).
  - `sync.jobs.ts`: worker handler `sync.run` (FULL | INCREMENTAL; cursor persisted on `SyncJob`), wired into `nightly.kickoff` as a BullMQ flow parent (ARCH §1.2 step 2).
  - `webhooks/route.ts`: Route Handler `POST /api/integrations/[provider]/webhook/[integrationId]`. It verifies the signature, stores the raw payload in storage, inserts `WebhookEvent` (deduped) and enqueues processing. Processing calls the real-time single-account signal evaluation hook from M3.
  - `writeback.service.ts`: `writeBack(integrationId, change)`. It refuses unless `writeBackEnabled && field ∈ writeBackFields`. Otherwise it creates an `Approval` of kind `WRITE_BACK` unless the step level allows auto. It writes an AuditLog row.
  - `describeError` → `Integration.lastErrorPlain` / `SyncJob.errorPlain`, written in plain words.
- **Adapters** (`src/modules/integrations/adapters/<provider>/`):
  - **HubSpot** (OAuth): companies→Account, contacts→Contact, owners→User mapping (by email, unmatched listed), deals→Contract when configured.
  - **Salesforce** (OAuth): Account, Contact, User owner, Opportunity→Contract when configured.
  - **Stripe** (API key, restricted read key recommended): customers→Account match (by domain/email/ExternalRef), subscriptions, invoices. Webhooks: `invoice.payment_failed`, `invoice.paid`, `customer.subscription.updated`.
  - **Chargebee** (API key): customers, subscriptions, invoices. Webhooks for payment failure/success.
  - **Slack** (OAuth bot):
    - posts signal and approval notifications (`Notification.channel = SLACK`) and a daily digest;
    - interactive Approve/Reject buttons on approvals via `POST /api/integrations/slack/interactivity`, with the Slack signing secret verified and the timestamp within 5 minutes;
    - a Slack user is mapped to a `Membership` by verified email. The decision runs through `approvals.service` with `requirePermission(ctx, "approvals:decide")` and the book-scope check, exactly as in the web UI.
- **Screens**:
  - Settings › Integrations: connect / disconnect / test connection per provider; sync status (last run time, counts, last error in plain words, "Run sync now"); write-back toggle + field picker (Admin only).
  - Settings › Data health: the dead-letter list from ARCH §1.2.
- **Setup wizard** (`/setup`, Admin):
  1. Connect (any launch integration from M5, or skip to CSV).
  2. Import (sync or CSV from M2).
  3. Proposed tiers + segments, using INTERP-3 tier rule and default segments, editable.
  4. Proposed health model + back-test sentence (M3 engine) → review/approve.
  5. Go live (enables the nightly scheduler for the workspace).
  The "proposed plays" step is explicitly a later step added in M8. The wizard shows 5 steps now and gets no placeholder box.
- **Env names** (names only in `.env.example`): `HUBSPOT_CLIENT_ID`, `HUBSPOT_CLIENT_SECRET`, `SALESFORCE_CLIENT_ID`, `SALESFORCE_CLIENT_SECRET`, `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_SIGNING_SECRET`, `STRIPE_WEBHOOK_SECRET` (per-integration secrets are stored encrypted in `Integration.credentialsEnc`), `FIELD_ENCRYPTION_KEY`.
- **Recorded fixtures**: `src/modules/integrations/adapters/<provider>/__fixtures__/*.json`, realistic fictional payloads (pagination, deletes, malformed records).

## 5. Tests to write FIRST
- `src/modules/integrations/__tests__/ingest.int.test.ts`:
  - upserting the same normalized batch twice creates no duplicates (ExternalRef unique);
  - an updated external record updates in place;
  - a record whose external owner is unknown is ingested with `ownerId = null` and listed as unmatched, never assigned to a random user;
  - normalized records failing Zod are rejected with a plain-words reason, and the rest of the batch continues.
- `src/modules/integrations/__tests__/webhook.int.test.ts`:
  - replaying the same `externalEventId` is a no-op;
  - an invalid signature returns 401 and stores nothing;
  - a valid Stripe `invoice.payment_failed` opens a `Signal` for the matched account within the same job.
- `src/modules/integrations/__tests__/writeback.test.ts`:
  - refused when `writeBackEnabled=false`;
  - refused for a field not in `writeBackFields`;
  - creates a `WRITE_BACK` Approval when allowed but the level is approval;
  - writes an AuditLog row in every path.
- `src/modules/integrations/__tests__/oauth.test.ts`: tampered `state` is rejected; tokens are stored encrypted (raw DB value ≠ token); refresh updates `credentialsEnc`.
- `src/modules/integrations/adapters/<provider>/__tests__/contract.test.ts` for each of hubspot, salesforce, stripe, chargebee, slack:
  - fixture payload → expected normalized output, including pagination and deleted/archived records;
  - `describeError` maps 401/403/429/5xx to plain sentences.
- `src/modules/integrations/adapters/slack/__tests__/interactivity.int.test.ts`:
  - a bad signature or stale timestamp is rejected;
  - an unmapped Slack user is rejected;
  - a mapped Viewer is rejected (no `approvals:decide`);
  - a mapped CSM outside the account's book is rejected;
  - a mapped CSM in book approves → `Approval.decidedById` set + AuditLog.
- `src/modules/integrations/__tests__/sync.int.test.ts`: an INCREMENTAL run resumes from the cursor; a failed page records `errorPlain` and does not advance the cursor; re-running the nightly flow is idempotent.
- **Tenant suite** (`src/lib/db/__tests__/tenant-isolation.test.ts`):
  - add `Integration`, `SyncJob`, `WebhookEvent`;
  - a webhook URL carrying workspace A's integrationId with B's payload signature fails;
  - workspace B cannot read A's integration status through any Server Action (action-enumeration test picks the new actions up).
