## 1. Goal
Build the audited agent runtime and the CSM's daily home. That covers the Today queue, the Approvals queue, the single approval-gated customer-send path with all guards, the first two agents (Health Analyst, Watcher-basic), the audit viewer/export and agent pages.

## 2. In scope
- **Prisma models ([W], RLS, registry):** AgentDefinition, AgentRun, Approval, OutboundMessage, EmailSuppression, TodayItem, Extraction. Notification already exists from M2.
  - Add the FK from every `agentRunId` column (M2/M3 tables) to AgentRun.
  - AgentRun CHECK: `status='SUCCEEDED'` ⇒ output, reasoningSummary, confidence, promptVersion, model NOT NULL.
  - Unique `(workspaceId, idempotencyKey)`.
  - Side-effect unique `sourceKey` on Approval/Task/OutboundMessage.
- **Agent framework** (`src/modules/agents/`):
  - `defineAgent` with the fields in ARCHITECTURE §6.1, plus the `BaseAgentOutput` Zod schema (`reasoningSummary`, `confidence`, `citations.min(1)`, `insufficientData`, `proposedActions`).
  - Registry; startup check that every agent's prompt file exists with matching `name`/`version`.
  - ContextBundle builder helpers, scoped only.
  - Executor job `agents.run`:
    - idempotency key `sha256(workspaceId, agentKey, agentVersion, triggerType, triggerId, inputHash)`;
    - QUEUED → RUNNING → SUCCEEDED / INVALID_OUTPUT / UNCITED / FAILED / SKIPPED;
    - structured output through a tool whose JSON Schema is generated from the Zod schema; one repair call;
    - **citation validator** (ids ∈ bundle; quotes verbatim substrings after whitespace normalization);
    - **forbidden-numeric overwrite**;
    - side effects after persist, keyed `(agentRunId, actionIndex)`;
    - retry 4× with backoff + jitter on 429/5xx/timeouts;
    - per-workspace daily token budget → SKIPPED "budget";
    - an AuditLog row per run.
  - With no `ANTHROPIC_API_KEY`, AI features show "AI is not configured" and no run is faked. `RecordedProvider` is for tests only.
  - `<AiText run>` component: renders only SUCCEEDED runs, with sources, a "model confidence" label and a "what it read" link; renders nothing otherwise.
- **Agents in M4:**
  - **Health Analyst** (`health-analyst`, tier standard).
    - Trigger: `health.bandChanged` or a top-reason change.
    - Context: snapshot, reasons, open signals.
    - Output: `items[{ text, citesReasonIds[], citesSignalIds[] }]` (max 2).
    - Internal only.
    - Prompt: `prompts/health-analyst.md` v1.0.0.
  - **Watcher-basic** (`watcher`, tier fast). It runs the extraction step (ARCHITECTURE §5.3) over **existing** Note and Ticket/Message text in the seed and writes `Extraction` rows (agentRunId NOT NULL, quote validated, idempotent by `(sourceType, sourceId, promptVersion)`).
    - In M4 the Sentiment pillar is fed from SENTIMENT extractions on ticket messages only, which wires the pipeline end to end.
    - Extraction→Signal text rules come in M9.
    - Prompt: `prompts/watcher-extraction.md` v1.0.0.
    - Golden set: `prompts/__golden__/extraction/` (initial ≥ 10 fixtures, replayed in CI).
  - `pnpm eval` script (live, outside the gate; add to CLAUDE.md Commands).
- **approvals module:**
  - Approval lifecycle PENDING → APPROVED / EDITED_APPROVED (with `editDiff`) / REJECTED / EXPIRED / SUPERSEDED.
  - Each Approval shows its reason + proof (sources).
  - The approval-level resolver (ARCHITECTURE §7.3): `effective = min(step level for tier, workspace ceiling, sensitive cap)`.
  - Bulk decide with an exact confirmation list.
  - Assignee = account owner (fallback CS Leader). CSMs decide only in their own book.
- **outbound module** (the single send path, Rule 3):
  - `src/modules/outbound/dispatch.ts` is the **only** importer of `src/lib/email/customerTransport.ts` (ESLint restricted import + import-graph test).
  - It sends only if:
    - (a) `sendMode=APPROVED` and the linked Approval is APPROVED/EDITED_APPROVED by a permitted user; **or**
    - (b) `sendMode=AUTO` and every guard passes.
  - It records `guardResults`, `sentAt`, `providerMessageId`, and writes an AuditLog row.
  - `evaluateGuards(ctx) → GuardResult[]`: a pure function implementing **all 8 guards** of ARCHITECTURE §7.4:
    1. contact emailed in the last 3 days;
    2. another play emailed the account in the last 48h;
    3. quiet hours in contact → account tz, with unknown tz = hold;
    4. open HIGH/URGENT/escalated ticket;
    5. lifecycleStage LOST;
    6. sensitive topic;
    7. suppression;
    8. auto-send master switch off.
    A failure → status HELD + an Approval is created; nothing is dropped silently.
  - `detectSensitive(text, extractions, stepTags)`: conservative OR of the keyword/regex list (cancel, price/pricing/discount, legal/contract terms/lawyer, security/breach/GDPR, complaint, escalation…), INTENT/CANCEL_LANGUAGE/COMPLAINT extractions, and sensitive step tags. A hit sets `Approval.isSensitive=true` and caps at DRAFT_FOR_APPROVAL, which no setting can override.
  - **Auto-send stays disabled until M8.** The workspace master switch is forced off and there is no UI to enable it in M4. Dispatch, `evaluateGuards` and the sensitive detector are nonetheless **fully built and tested now**, and every send (approved ones included) passes through dispatch.
  - Suppression list (EmailSuppression); in dev the transport is log-only.
- **Approved drafts in M4.** M4 creates customer drafts through one internal action: a CSM can ask for a check-in draft from a signal ("Draft check-in"). Health Analyst output itself is internal-only.
  - That action creates OutboundMessage DRAFT + Approval.
  - If AI is configured, it runs the **Outreach Agent in basic form** (`outreach`, `prompts/outreach.md` v1.0.0, tier standard, cites signal/reason ids). It drafts one email for one approved intent. Otherwise a human writes the draft.
  - No agent outside the spec's 13 + Ask AI is added (D-30). M8 extends the same `outreach` agent with play-step intents, voice samples and per-step approval levels.
- **today module:**
  - Deterministic `rankScore = moneyWeight × urgency` (ARCHITECTURE §9) with `rankReasons`.
  - Sections: Tasks due/overdue, New signals, Meetings (honest empty state until M10: "No calendar connected"), Approvals waiting, Renewals ≤ 90d.
  - Own book only.
  - `today.rebuild` job nightly and on relevant events; paginated 25/section.
  - ARR hidden without `canViewRevenue`.
- **tasks:** an overdue-escalation job (`task.overdue` → Notification + a CS Leader Today item).
- **audit module:** `/settings/audit` viewer (filters: actor, action, target, date; paginated) + CSV/JSON export (Admin; CS Leader view-only per RBAC). The export is itself audited.
- **Agent pages:** `/settings/ai-team` (each agent: enabled, tier, recent runs; run detail = inputRefs links, output, reasoning, confidence, actionTaken, approval decision).
- **outcomes:**
  - `actionTaken` tracking: ACTED when a linked approval is approved, a task completed, a message sent or a play step run; IGNORED if nothing by day 7.
  - The `outcomes.checkpoint` daily job evaluates the **7-day** checkpoint for REPLIED and RECOVERED, with evidence sources.
- **Screens:** `/today` (becomes the post-sign-in landing page), `/approvals`, the Account 360 Health tab with the Health Analyst narrative via `<AiText>`, `/settings/audit`, `/settings/ai-team`.

## 5. Tests to write FIRST
- `src/modules/agents/__tests__/citations.test.ts`:
  - a citation id not in the bundle → UNCITED;
  - a quote not a verbatim substring → UNCITED;
  - an empty citations array → Zod fail;

  - SUCCEEDED rows have all audit fields (Rule 5);

  - a crash after persist + retry → no duplicate Approval/Task (sourceKey);
  - budget exceeded → SKIPPED;
  - no API key → "not configured", no run.
- `src/modules/agents/__tests__/forbidden-numeric.test.ts`: agent-supplied `confidence`/money fields in proposed actions are overwritten from deterministic code.
- `src/modules/conversations/__tests__/extraction-validate.test.ts`: invented quote dropped; PROMISE without a parseable date → null with a flag; per-kind Zod payloads.
- `prompts/__golden__/extraction/replay.test.ts`: recorded responses → expected Extraction rows.
- `src/modules/outbound/__tests__/guards.test.ts`: each of the 8 guards fails/passes in isolation. Notable cases:
  - **unknown time zone → hold**;
  - 47h vs 49h boundary for the other-play guard; 2d23h vs 3d1h for the contact guard;
  - LOST never;
  - a sensitive topic never auto, even when every other guard passes and the master switch is on (simulated config).
- `src/modules/outbound/__tests__/sensitive.test.ts`: keyword cases ("cancel", "refund", "price increase", "our lawyer", "security incident", "complaint", "escalate"); extraction-driven cases; a false-positive tolerance note (conservative by design).

  - send without an approved Approval throws;
  - a REJECTED approval cannot send;
  - a suppressed address never sends, even if approved;
  - AUTO with the master switch off → HELD + Approval;

- `src/modules/outbound/__tests__/import-graph.test.ts`: only `dispatch.ts` imports `customerTransport`.
- `src/modules/approvals/__tests__/level-resolver.test.ts`: tier defaults; workspace ceiling; sensitive cap wins.
- `src/modules/today/__tests__/ranking.test.ts`: money × urgency ordering; overdue growth cap; tie-breaks; own-book filter; ARR hidden without permission but ranking unchanged.
- `src/modules/outcomes/__tests__/actioned.int.test.ts`: ACTED / IGNORED transitions; the 7-day REPLIED and RECOVERED evidence.
