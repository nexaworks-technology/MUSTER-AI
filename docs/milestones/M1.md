- **Tenancy infrastructure (ARCHITECTURE §7.1).**
  - `src/lib/db/raw.ts`: the raw PrismaClient, import-restricted by ESLint to `src/lib/db/**`, `src/lib/auth/**`, `prisma/seed.ts` and the outbox dispatcher.
  - `src/lib/db/scoped.ts`: `scopedDb(ctx)`, a Prisma client extension that:
    - injects `workspaceId` into where/data for every [W] model;
    - throws on a mismatched `workspaceId`;
    - throws on `$queryRawUnsafe`;
    - wraps each operation in a transaction beginning `SELECT set_config('app.workspace_id', $1, true)`.
  - `src/lib/db/tenantModels.ts`: the registry of [W] models.
  - Migration helper `prisma/sql/rls.sql.ts` (or a documented SQL template) that emits `ENABLE` + `FORCE ROW LEVEL SECURITY` + a policy per [W] table.
  - The composite-unique `@@unique([workspaceId, id])` + composite-FK convention, documented in `prisma/README.md`.
- **Auth (D-07, D-08).**
  - Auth.js v5 with Google + Credentials and **database sessions**. The Auth.js Credentials provider natively only issues JWT sessions, so implement as follows:
    1. **`authorize()` verifies only.** It checks email + `passwordHash` (argon2id) and returns the user.
    2. **The `signIn` callback creates the session row.** It runs only for `credentials`. It generates a random 32-byte `sessionToken`, then calls `adapter.createSession({ sessionToken, userId, expires })`.
    3. **Set the cookie.** Write the standard Auth.js session cookie (same name, `httpOnly`, `secure` in prod, `sameSite=lax`) via `cookies().set`.
    4. **Override the JWT config.** `jwt.encode` returns that `sessionToken` for credentials logins, and `jwt.decode` returns `null`, so Auth.js reads the session from the database through the adapter.
    5. **Keep the session strategy.** `session.strategy = "database"`.
    6. **Document it.** Write this in `src/lib/auth/README.md` with a test.
  - **Custom adapter (D-08).** It wraps `@auth/prisma-adapter` and overrides every method that touches `prisma.account` (`linkAccount`, `unlinkAccount`, `getUserByAccount`, plus `deleteUser` cascade) to use the `AuthAccount` model instead. Our `Account` name stays reserved for customer accounts. OAuth tokens in `AuthAccount` are encrypted via `src/lib/crypto`.
  - `src/lib/auth`: `getSession()`, `getWorkspaceContext()` (membership lookup; the client never supplies `workspaceId` for authz), `requirePermission(ctx, perm)`, and a permission map implementing the ARCHITECTURE §7.2 matrix incl. `canViewRevenue`.
  - Workspace switcher (sets `Session.activeWorkspaceId`).
- **settings module.**
  - Settings › Users: list members, invite by email (Invitation with hashed token, 7-day expiry, accept route `/invite/[token]`), change role / `canViewRevenue` / `bookScope`, deactivate. Admin only.
  - Settings › Workspace: name, timezone, base currency (Q-12).
- **`src/lib/audit`:**
  - `audit.write({ actorType, actorId, action, targetType, targetId, summary, before?, after? })` with redaction;

- **`src/lib/jobs`:**

  - outbox write helper + dispatcher;
  - worker entry `src/worker/index.ts` with a `maintenance.heartbeat` job.
  - `pnpm dev` runs the web app + worker.
- **`src/lib/ai`:**

  3. Passing `workspaceId: B` explicitly to A's client throws.
