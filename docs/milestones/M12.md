## 1. Goal
Make the product pilot-ready: proven tenant safety across every action, data export/delete, security headers and rate limits, performance at 2,000 accounts, observability, pilot instrumentation, a container deploy to staging, an honest security overview, and a full regression.

## 2. In scope
- **Data controls (§6N7)** in `src/modules/settings/data-controls/`:
  - **Export.** An Admin requests it; job `maintenance.exportWorkspace` builds a ZIP of JSON/CSV per [W] entity plus files, using a 7-day signed link. Audited.
  - **Delete.**
    - Admin typed confirmation sets `Workspace.deletionRequestedAt`.
    - After the grace period (default 7 days, config), job `maintenance.purgeWorkspace` deletes all [W] rows and `ws/<workspaceId>/` S3 prefixes. The append-only AuditLog trigger permits a purge only in this job.
    - A non-tenant tombstone record is written. The UI states the timeline per Q-10 ("within 30 days").
  - A DPA-ready data map in `docs/DATA_MAP.md`: entities, purpose, retention, subprocessors (Anthropic, Resend, object storage host, error tracking per Q-20).
- **Tenant safety completion (Rule 2):**
  - The enumeration test iterates **every** registered Server Action, Route Handler (incl. portal, webhooks, Slack interactivity, usage API) and Ask AI tool, and asserts that workspace B ids return 404/notFound for a workspace A session.
  - The model-registry test asserts that every [W] model has workspaceId, an RLS policy, FORCE RLS and the composite unique.
- **RBAC.** A full matrix test (ARCHITECTURE §7.2) for each role × permission, plus `canViewRevenue` redaction across every financial view and export.
- **Security hardening:**
  - CSP + security headers (HSTS, X-Content-Type-Options, frame-ancestors none except where required, Referrer-Policy).
  - Rate limiting (Redis) on sign-in, invitation accept, webhooks, portal magic link, usage API and Ask AI.
  - Session cookie flags.
  - `pnpm audit` clean or every finding documented.
  - A secret-scan script in CI.
  - The log redaction test (tokens, credentialsEnc, email bodies, AI content never logged).
  - The malware scanner configured for prod per Q-18. The boot check refuses prod without one.
- **Rule 8 verification (Q-19).** Record the AI provider's commercial data terms (no training on API data) with a date and link in `docs/SECURITY.md`. A test confirms no cross-workspace data appears in any prompt bundle (bundle source ids all belong to the run's workspace).
- **Encryption & backups.**
  - Document encryption in transit (TLS) and at rest (managed Postgres/S3 settings) for the chosen host.
  - Write a backup schedule and a **restore drill**: restore the latest backup to a scratch DB, run smoke checks, and record the timestamps.
- **Performance (ARCHITECTURE §11):**
  - A synthetic generator `pnpm db:seed:scale --accounts 2000` (seed tooling only, Rule 6).
  - The nightly run (sync skipped, signals + health + today rebuild + checkpoints) must finish within a documented budget (target ≤ 20 min on the staging size; record the actual).
  - Query-budget tests for every list/360 screen; cursor pagination verified.
- **Observability:**
  - pino structured logs (redacted), with a request id and job id.
  - A Bull Board job dashboard at `/settings/system/jobs` (Admin-only).
  - An error-tracking adapter behind an env DSN (Q-20), a no-op when absent.
  - Health endpoints `/api/health` (web) and a worker heartbeat.
- **Pilot instrumentation (§11).** A `ProductEvent` capture (internal, [W] scoped; add to QUESTIONS.md if this entity needs approval) for Today/Approvals opens per CSM per week, flag acceptance rate, QBR/brief prep time (generated → shared). Shown in Reports › "Pilot metrics" (Admin/Leader).
- **Deploy (Q-13 default: container-based, host-agnostic):**
  - Production Dockerfiles for web and worker (multi-stage, non-root user), migrations run as a release step with the owner role, and the app running as `app_user`.
  - An env checklist (`docs/DEPLOY.md`) built from the Zod env schema.
  - A staging environment and a smoke suite `e2e/smoke.spec.ts` against staging.
- **Setup end-to-end (§6O1).** A fresh workspace → setup wizard (CSV + Stripe test mode) → day-1 Today queue, verified by e2e.
- **Docs:**
  - `docs/ADMIN_GUIDE.md`, `docs/SETUP_GUIDE.md`.
  - `docs/SECURITY.md`: an honest security path — SOC 2-aligned controls, SOC 2 Type II as a dated roadmap item, **no certificate claims**.
  - `docs/RULES_CHECK_MAP.md`.
- **Full regression.** All milestone e2e demo specs M1–M11, plus `e2e/m12-hardening.spec.ts`.

- **Carried verifications (each was deferred with M12 as its home; "done" is stated per item):**
  - **Live connector checks (M5, M6).** Read-only checks against sandbox or test-mode accounts for HubSpot, Salesforce, Stripe, Chargebee, Slack, the Usage API with Segment's webhook destination, Mixpanel and Amplitude: connect, sync twice (second run changes nothing), webhook or signature verification where the provider has one. Done = a per-provider table in M12-LOG with timestamps, or **DEFERRED** with the reason (no credentials). First-live fixes are expected and in scope: Amplitude's segmentation response shape, Mixpanel's `time` zone reading, Segment's `x-signature` scheme.
  - **Live Resend (M4).** One real send through `outbound.dispatch` to a test address with `RESEND_API_KEY` set, and its delivery webhook (the same dependency as M8 #17). Done = message id and timestamps in M12-LOG, or **DEFERRED**.
  - **Live write-back (D-116).** With `WRITE_BACK_LIVE=true` on a sandbox HubSpot or Salesforce, one approved account-owner write-back pushes and is audited; with it unset the push is refused. Done = log, or **DEFERRED** with no sandbox.
  - **Docker #16 (M1).** `docker compose up -d postgres redis minio` run successfully on a machine with Docker, the output recorded in `M1-LOG.md`. Done = acceptance #16 changes from PARTIAL to PASS there (and in `IMPLEMENTATION_PLAN.md`), or stays PARTIAL with the reason.
  - **Nested `scopedDb` reads (Q-54, found in M5).** A `scopedDb` read inside a `$tenantTransaction` callback runs on another connection without the workspace setting. Done = every such call found and fixed, and a lint rule or test that fails on a new one.
  - **E2E web server on the recorded AI provider (Q-47).** Either the e2e web server gets `AI_PROVIDER=recorded` and `AI_RECORDINGS_DIR` (a founder-approved edit to `playwright.config.ts`), so the in-app "Ask AI to draft" path is covered, or Q-47 is closed as not needed. Done = the founder's decision recorded in QUESTIONS.md.
