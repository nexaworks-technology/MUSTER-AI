## 1. Goal
Build one true account view from CSV, manual entry and seed data: the Accounts list, and an Account 360 with people, contracts, usage, tickets, conversations, tasks, notes and a full timeline. It also includes the missing-data helper, the data-quality checker and segments.

## 2. In scope
- **Prisma models.** Every one is [W]: `workspaceId`, `@@unique([workspaceId,id])`, composite FKs, RLS, and registered in `tenantModels.ts`.
  - Accounts & people: Account, Contact, StakeholderRole, Segment, Note, NoteTemplate, DataQualityIssue, MissingDataPrompt.
  - Commercial: Contract (with `termsEnc`, `pricingNotesEnc`), Subscription, Invoice, RevenueEvent.
  - Usage: UsageDaily, UserUsageDaily, FeatureUsageDaily, FeatureCatalog.
  - Support & conversations: Ticket, Conversation, Message, CallTranscript (model only, no UI ingest yet).
  - Work and plumbing: Task, Notification, ExternalRef, FileObject.
  - Every row carries `source` (CSV | MANUAL | SEED | …) and, where AI could write later, `origin` + `agentRunId` with the CHECK `origin <> 'AI' OR agent_run_id IS NOT NULL`. The `agentRunId` FK target lands in M4, so add the column now as nullable text and the FK in M4's migration.
- **Services** (`service.ts` + `schemas.ts` per module):
  - `accounts`:
    - CRUD, tier rule + manual override (INTERP-3; thresholds in `WorkspaceSettings`);
    - `lastTouchAt` derivation;
    - the timeline assembler (merges Message, Ticket, Invoice, UsageDaily change points, Note, Task, StakeholderRole changes, Contract events; time-ordered, cursor-paginated);
    - the missing-data helper;
    - the data-quality checker.
  - `contacts`: stakeholder map, champion designation (StakeholderRole history with validFrom/validTo).
  - `billing`:
    - contracts/subscriptions/invoices;
    - `RevenueEvent` derivation by rule (NEW, EXPANSION, CONTRACTION, CHURN, REACTIVATION from contract/subscription changes; `computedBy: RULE`);
    - `Account.arrMinor` derivation;
    - `redactFinancials` projection for users without `canViewRevenue`;
    - encryption of terms/pricing notes via `src/lib/crypto`.
  - `usage`: ingest + window queries (SQL aggregates).
  - `support`, `conversations`: read models for the 360 tabs.
  - `tasks`: manual create/assign/complete, due dates.
  - `notes`: templates per call type, tags, @mentions → in-app `Notification`.
  - `segments`: a Zod-validated filter DSL (fields: stage, plan, tier, industry, owner, ARR band, renewal date range, any Account scalar). Dynamic evaluation compiles to a Prisma `where`; the health filter is added in M3.
- **CSV import** (`accounts` module, `src/modules/accounts/import/`):
  - Downloadable templates for accounts, contacts, contracts, invoices, usage (account-daily, user-daily, feature-daily) and tickets (+ ticket messages).
  - Upload via `src/lib/storage` with the §7.6 checks (size, sniffed MIME = csv).
  - Column mapper, dry-run preview with row-level errors in plain words ("Row 14: renewal date '31/13/2026' is not a date").
  - Commit as a background job (`sync` queue), with idempotent upsert keyed by `ExternalRef(source=CSV, objectType, externalId)`.
  - Import summary (created/updated/skipped/errors).
  - **Outside-signal CSV is deferred to M3.** The Signal model and rules land there, which avoids a throwaway staging table.
- **Screens:**
  - `/accounts`:
    - table with search, filters, saved segments, cursor pagination (50), inline edit (owner, tier, stage, renewal date);
    - columns: Name, Tier, Stage, Owner, ARR (Restricted without revenue permission), Renewal date, Last touch;
    - Health column hidden until M3.
  - `/accounts/[id]` (Account 360) tabs:
    - Overview, People, Usage (charts only from real rows; "No usage data yet" otherwise), Tickets, Conversations;
    - Contracts & billing ("No contract on file" empty state; values gated);
    - Tasks, Notes, Timeline.
  - Missing-data prompt inline on Overview: one question, Answer / Skip, snooze 30 days per Q-09, never nags daily.
  - `/settings/data-quality`: issues list, suggested fix preview, Confirm (single) and Confirm all (bulk, with an exact change list). No change without confirmation.
  - `/settings/import`: the CSV import flow.
  - `/tasks` (my tasks), notification bell.
- **Seed v1:** the full raw demo dataset per `docs/SEED_DATA.md` (accounts, contacts incl. Maya Ortiz at Brightwell Logistics, contracts, 90 days usage, tickets incl. Halden Retail's repeat CSV-export tickets, messages/transcripts text, invoices incl. Sundial Fitness failures, historical churned/renewed accounts). No HealthScoreSnapshot/Signal rows.
- Nav: Accounts and Tasks become visible.

## 5. Tests to write FIRST

  - Contact → Account of another workspace (composite FK fails);
  - `/accounts/[id]` with Tenant B's id → 404 (route test);
  - CSV import into A never touches B even with the same externalIds.
- `src/modules/billing/__tests__/redact-financials.test.ts`: without `canViewRevenue`, every money field (Contract.valueMinor, Account.arrMinor, Invoice.amountMinor, RevenueEvent.deltaArrMinor, Subscription.amountMinor) is absent from every service return; terms are never decrypted for such users.
- `src/modules/billing/__tests__/revenue-events.test.ts`: new contract → NEW; seat increase → EXPANSION; decrease → CONTRACTION; ended without renewal → CHURN; idempotent recompute.
- `src/modules/accounts/__tests__/tier-rule.test.ts`: ARR band edges (exactly 10k / 50k); manual override survives re-derivation; no ARR → tier unchanged (missing data never moves an account down).
- `src/modules/accounts/__tests__/timeline.test.ts`: merge order, ties, pagination cursor stability.
- `src/modules/accounts/__tests__/missing-data.test.ts`: one open prompt per field; skip snoozes 30d; answered never re-asks; asks only the owner (or an Admin when no owner).
- `src/modules/accounts/__tests__/data-quality.test.ts`: duplicate detection cases; fix not applied without `confirm: true`; bulk applies exactly the previewed list.
- `src/modules/accounts/import/__tests__/csv-import.test.ts`: plain-words errors; dry-run writes nothing; re-import = 0 creates; malformed MIME rejected.
- `src/modules/segments/__tests__/filter-dsl.test.ts`: Zod rejects unknown fields; compiled `where` always includes the scoped workspace (asserted through `scopedDb`).
- `src/modules/accounts/__tests__/query-budget.int.test.ts`: the Accounts list page of 50 and Account 360 load stay ≤ a fixed query count (Prisma query event counter).
