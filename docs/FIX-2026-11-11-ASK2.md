## Root causes

**Cited refs it "was not given" (item 2).** Two different things, neither a leak from the planner:
1. **A copied id was corrupted.** The error says the draft cited Signal `cmw9dfjqk00hqlj2t9xqlyca8`. The signal that exists, and *was* in the run's 150 records, is `cmw9dfjqk00hqlj2t6tiqd24b`. The model copied the first 17 of 25 characters and **invented the tail**. (Your report spells it `…hqjl2…`; neither spelling exists in the database.) Asking a model to copy long random ids "exactly" fails at a small but steady rate, and a 150-record bundle makes it likelier.
2. **An account it was never given as a record.** `seed918789…` exists (Silverline Couriers Inc.) but was not among the 150 records; the model cited the account a signal belongs to, which appeared only as a field value. Fixed at the source by the portfolio tool (below), whose records carry the account's id and name, and by the prompt's "only handles shown below".
3. **"the number 56 from no cited record"** is the guard working: a count the model wrote that no cited record contains. The portfolio tool puts the counts in a record the answer can cite.

**Timeouts (item 3).** `MAX_ATTEMPTS = 5` retried a timeout, each at the 60 s request timeout, plus backoff. Run 1's 255 s is three timeouts then a success; run 2's 277 s is five timeouts. Interactive and background runs shared that policy.

**Page crash (item 4).** The action already catches errors and returns "I could not answer that…", so a server exception would not have shown the error boundary. The crash text ("Something went wrong… reference: none", no digest) is the client-side boundary, which fits the request being **cut off before the action returned**. Two things then compound: (a) a **planning-step timeout was not caught** (`catch` rethrew everything except "not configured"), so the question failed with nothing saved; (b) the questions ran 255 to 277 s, past the **100 s limit of the Cloudflare tunnel** in front of the Docker demo (and any similar proxy). I could not reproduce the exact crash through the tunnel, so (b) is inferred from the timings and the error text; (a) is certain and fixed.

## Fixes

1. **One-call portfolio tool** (`getPortfolioHealth`, no input). `portfolioHealth()` in `src/modules/health/service.ts` returns the band counts and the lowest-scoring At Risk then Watch accounts (up to 10), each with up to three of its most negative evidence reasons and their real ids: the same snapshot the Health page shows (latest live one under the active model), limited to the member's book, ARR only with revenue access, lost and archived accounts excluded. The Ask tool turns it into a `PortfolioHealth` record (counts) plus one `HealthScoreSnapshot` record per account (name, score, band, `reason1..3`), with a note when the list is cut ("10 lowest-scoring of 15 … not the full list"). It has **no filter**: my first live run passed `band: AT_RISK` on a book with 0 At Risk and 1 Watch, got no accounts back and could not name the Watch one, so a planner-settable filter was removed.
2. **Short cite handles** (`src/modules/agents/aliases.ts`). Each record is shown with a handle (`R1`, `R2`, …); citations may use it, and code maps the handle to the real `(sourceType, sourceId)` **before** the unchanged checker runs. It never widens what can be cited: an unknown handle (`R99`), a real id that was not a record in this run, and a mangled id are all left as written and refused; the handle is not part of a record's fields, so it cannot make a number appear. Real ids still work. Prompt `ask-ai` 1.0.0 → 1.1.1 (cite by handle; only handles shown below; no numbered lists).
3. **Attempts and timeouts.** `ExecutorDeps.interactive` (used for Ask AI): at most **2 attempts in all**, and **a timeout is never retried**. Background jobs keep the patient 5-attempt policy. A per-request `timeoutMs` reaches the SDK.
4. **A time limit for the whole question** (`loop.ts`): 80 s overall; planning gets a 25 s budget and 20 s per call; the answer call gets whatever is left (15 to 60 s). A planning failure no longer throws: with records already retrieved it answers from them; with none it makes no answer call and saves an honest message. A timeout ends the question once with "That took too long, so I stopped. Nothing was saved as an answer. Try again, or ask about one account or one topic." The page now shows the stored sentence instead of a fixed one.
5. A planning failure with nothing retrieved is recorded as a **failed `ask-ai` run** (planning tokens recorded), because the database requires every assistant message to link to a run (`ask_message_agent_run_required`). That rule was kept, not bypassed.
